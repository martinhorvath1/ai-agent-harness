## Placement

| Function | Verdict | Reason |
|---|---|---|
| `run` (`src/core/game/registry.ts`) | KEEP | Dispatch is the core's public entry point; `src/cli/main.ts` is its only caller by design. Moving it into `src/cli` would put orchestration in the shell and break `core-no-cli`/the core-shell convention. 100% envy is the expected shape for a leaf consumed by the layer above. |
| `renderFrame` (`src/core/rules/frame.ts`) | KEEP | Pure rendering rule; `game/session.ts` is its only production caller and it is re-exported as public API. `rules/` below `game/` is exactly the planned arrow. (Its *signature* is finding #1; its *location* is right.) |
| `applyMove` (`src/core/rules/move.ts`) | KEEP | One command's behaviour, sequenced by `game/turn.ts`. Moving it into `game/` would collapse the rules layer. |
| `newGame` (`src/core/rules/new-game.ts`) | KEEP | Same: a rule invoked once by `turn.ts:startGame`. It also owns the opening-board contract the locked baseline hardening test drives. |
| `parseSeed` (`src/core/rules/seed.ts`) | KEEP | Env-string validation is logic, not I/O; `src/cli` reads `process.env` and hands the string in. Moving it to `src/cli` would put validation logic in the shell, against the core/shell convention. |
| `seededRandom` (`src/core/rules/seed.ts`) | KEEP | The injected random source must be constructible without touching the core's randomness ban; `src/cli` is the injector, so one caller is correct. Moving it to `src/cli` would duplicate the PRNG outside the tested core. |
